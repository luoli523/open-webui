# 语音工作台执行计划

日期：2026-09-30。状态：功能已实现并部署；浏览器视觉及真实麦克风验收待补。任务清单见 todo.md。

## 目标与范围

在 Open WebUI 增加「语音工作台」，完成选择音色、输入文案、生成、试听、下载、发送 Telegram，以及上传或现场录音并保存为可复用音色的完整流程。包含生成历史及音色管理。

本期提供 MP3/WAV、可选参考原文、本地自动转写、固定朗读文本录音、单个默认 Telegram 目标。上传后可选择自动识别并修正原文，或仅用录音创建音色。音频波形裁剪、多目标管理、批量生成、流式播放留待后续；已有预设音色的风格参数按能力显示。

## 已核实的基础

- ../local-tts：127.0.0.1:8091，OpenAI 兼容 speech 接口，离线 MLX 推理。
- CustomVoice 与 Base 1.7B 8bit 均有本地缓存。voice=guige 切换 Base；其他预设音色使用 CustomVoice。
- guige 与 luwei 均有 reference.wav/reference.txt；luwei 已有独立生成脚本及音频，但 HTTP 列表尚未注册。
- local-tts 已有单工作线程、8 个进行中/排队请求上限、分段、空闲释放和 MP3/WAV 转换。
- fin-report 依赖原有 guige ID；已有 Telegram 配置和基于内容摘要的发送回执机制。

## 架构决策

1. local-tts 是音色素材与推理的唯一管理方。WebUI 通过后端 HTTP 调用，不直接操作其目录；保留已有 speech 请求兼容性。
2. local-tts 动态注册预设/克隆音色。每个克隆音色有稳定 ID、显示名、可选参考原文、克隆模式、录音、版本、时间和来源。版本绑定素材，改名不改 ID。
3. WebUI 数据库记录音色与用户的关联、生成任务、历史和发送回执。已有 guige/luwei 作为管理员管理的既有音色；新音色默认私有。WebUI 对列表、试听、生成和下载逐项鉴权。
4. 上传/录制共用创建接口。后端验证音频实际可解码、大小、时长及非空时的原文，转成模型所需 WAV，原子提交；失败不留下半成品。不允许客户端指定服务器文件路径。
5. 原文为空时规范化为 None，使用仅录音的说话人特征路径；有原文时使用录音与原文参考路径。先验证本机 MLX 的两条路径及实际音质，不将代码支持等同于已通过试听。提供本地自动转写按钮，结果可编辑；转写失败仍可仅用录音保存，不自动切换到云端。模式及原文参与素材版本和缓存标识。
6. 更新参考素材产生新版本；正在执行的任务固定素材版本，清理须避开使用中的版本。删除采用先隐藏、后清理，已有播报仍可下载。
7. 生成采用持久化任务和单进程调度，复用 local-tts 的全局推理队列。任务含用户、文案、音色版本、模型/参数、状态、音频及错误。重启将遗留运行任务标记中断，不自动重复提交。多 worker 部署须采用数据库原子领取或限制单 worker。
8. 生成结果持久保存，页面轮询状态；音频完整生成后试听。先按所选格式生成，另一个格式按需转码并缓存，避免为了下载重复推理。
9. Telegram 由 WebUI 后端发送已生成的 MP3。服务端保存 Token；目标显式配置。按用户/目标/音频摘要记录发送请求，防止双击及并发重复；不确定结果进入待确认状态，不自动重发。
10. 部署时核实 WebUI 是否在容器内；127.0.0.1 必须指向真正的 local-tts。优先保持 local-tts 的回环监听，按现有部署设计访问路径。
11. 浏览器录音需核实实际访问地址、浏览器权限及安全上下文；不支持录音时仍提供文件上传。录音停止/页面退出时释放麦克风。

## 主要验收场景

- guige、luwei 和预设音色均可选；fin-report 的原 guige 请求继续可用。
- 上传录音不填原文也可命名保存并合成；填写或自动转写原文后可使用录音与原文参考路径，刷新/重启后模式保持。
- 自动转写结果可修正；失败不阻塞仅录音保存；参考原文与播报文案分别保存。
- 浏览器现场录音可开始、停止、回放、重录，按固定文本录制后可保存使用。
- 生成中可离开并返回；成功后试听、下载 MP3/WAV；失败显示可操作原因。
- 重命名不破坏任务；替换素材不混用旧缓存；删除音色不删除历史播报。
- 不同用户无法操作彼此私有音色、任务或音频。
- TG 成功显示回执；双击只创建一次发送；结果不确定时提示核对。
- 服务离线、队列满、坏音频、转码失败、录音权限拒绝、重启中断均有明确状态。
